# Установка

Инструкция от пустой машины до работающего бота. Части 5–7 необязательны:
без них бот работает, просто без сервера, голосовых и автоприёма СМС.

## 1. Что понадобится

**Обязательно:**

- **Node.js 22 или новее.** Проверить: `node --version`.
  Если нет — [nodejs.org](https://nodejs.org) или `brew install node`.
- **Подписка Claude Max.** Бот работает через неё, а не через API-ключ,
  поэтому токены не тратятся. Понадобится установленный
  [Claude Code](https://claude.com/claude-code).
- **Аккаунт в Телеграме.**

**По желанию:**

- **VPS** — чтобы бот работал, когда компьютер выключен. Хватит самого
  дешёвого: 1 ядро, 2 ГБ памяти, Debian или Ubuntu.
- **Мак** с пересылкой СМС с айфона — для автоматического приёма трат.

## 2. Создать бота в Телеграме

1. Напиши [@BotFather](https://t.me/BotFather), отправь `/newbot`
2. Придумай имя и username (должен заканчиваться на `bot`)
3. Сохрани токен — строку вида `1234567890:AAE...`

> Токен даёт полный доступ к боту. Не публикуй его и не отправляй в чаты.
> Если засветил — `/revoke` у BotFather выдаст новый.

## 3. Поставить локально

```bash
git clone https://github.com/fwexxo/fin-consultant-bot.git
cd fin-consultant-bot
npm install
```

Если `better-sqlite3` не собирается, поставь инструменты сборки:
`xcode-select --install` на маке, `apt install build-essential python3` на Linux.

Создай файл настроек:

```bash
cp .env.example .env
```

Открой `.env` и впиши токен бота:

```
TELEGRAM_BOT_TOKEN=1234567890:AAE...
OWNER_ID=
```

`OWNER_ID` пока оставь пустым — узнаем на следующем шаге.

Создай базу и наполни её:

```bash
npm run migrate
npm run seed
```

`seed` создаёт два счёта в базовой валюте — этого хватит, чтобы начать.
Остальное проще завести словами через бота:

```
заведи счёт для наличных в польских злотых
добавь валюту сингапурский доллар
добавь платёж за интернет 30 евро 15 числа
переименуй Карту USD в Основную
```

Базовая валюта задаётся в `.env` переменной `BASE_CURRENCY` — любой код
из таблицы `currencies` (по умолчанию USD). Валюты, которой нет в списке,
достаточно попросить у бота: он знает, что у иены нет дробной части,
а у динара их тысяча.

Запусти:

```bash
npm start
```

Напиши боту `/start` в Телеграме. Он ответит **твоим числовым ID** — впиши
его в `.env` как `OWNER_ID` и перезапусти бота.

> Доступ проверяется по числовому ID, а не по username: username в Телеграме
> можно сменить и передать другому человеку, ID — нет. Все остальные бот
> молча игнорирует.

## 4. Подключить Claude

Бот использует твою подписку Max через долгоживущий токен:

```bash
claude setup-token
```

Команда откроет браузер. Полученный токен впиши в `.env`:

```
CLAUDE_CODE_OAUTH_TOKEN=sk-ant-oat...
```

Перезапусти бота и напиши ему «кофе 5 руб». Если записал — готово.

**Что происходит под капотом.** Claude Agent SDK запускает `claude` CLI
отдельным процессом. Поэтому CLI должен быть установлен и доступен в `PATH`
на той машине, где работает бот.

## 5. Развернуть на сервере

Чтобы бот отвечал круглосуточно, а не только при включённом компьютере.

### Подготовка

Настрой вход по SSH-ключу без пароля:

```bash
ssh-copy-id root@ТВОЙ_СЕРВЕР
ssh root@ТВОЙ_СЕРВЕР 'echo вход работает'
```

Поставь на сервере Node 22 и Claude CLI:

```bash
ssh root@ТВОЙ_СЕРВЕР 'bash -s' <<'EOF'
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt-get install -y nodejs sqlite3
npm install -g @anthropic-ai/claude-code
node --version && claude --version
EOF
```

### Настройки на сервере

Секреты заводятся руками и **не** передаются скриптом выката — так они
не попадают ни в git, ни в историю команд:

```bash
ssh root@ТВОЙ_СЕРВЕР 'mkdir -p /opt/fin-bot && cat > /opt/fin-bot/.env' <<'EOF'
TELEGRAM_BOT_TOKEN=твой_токен
OWNER_ID=твой_id
BASE_CURRENCY=BYN
DATABASE_PATH=/opt/fin-bot/data/finance.db
TZ=Europe/Minsk
REMINDER_HOUR=10
CLAUDE_CODE_OAUTH_TOKEN=твой_oauth_токен
EOF
ssh root@ТВОЙ_СЕРВЕР 'chmod 600 /opt/fin-bot/.env'
```

### Выкат

```bash
./deploy/deploy.sh root@ТВОЙ_СЕРВЕР
```

Скрипт соберёт проект, зальёт `dist/`, заведёт пользователя `finbot`,
поставит systemd-юнит и запустит сервис.

Наполни базу на сервере:

```bash
ssh root@ТВОЙ_СЕРВЕР 'cd /opt/fin-bot && sudo -u finbot env HOME=/opt/fin-bot node dist/db/seed-cli.js'
```

Проверь:

```bash
ssh root@ТВОЙ_СЕРВЕР 'systemctl status fin-bot --no-pager'
ssh root@ТВОЙ_СЕРВЕР 'journalctl -u fin-bot -f'
```

### Бэкапы

```bash
ssh root@ТВОЙ_СЕРВЕР '(crontab -l 2>/dev/null; echo "30 3 * * * /opt/fin-bot/backup.sh >> /var/log/fin-bot-backup.log 2>&1") | crontab -'
```

Хранятся 30 последних копий. Снимаются через `sqlite3 .backup`, а не `cp`:
при включённом WAL обычное копирование может застать базу в несогласованном
виде.

### Про память

Юнит ставит `MemoryMax=1100M`. Это не запас на глазок, а сумма замеров:
сам бот ~50 МБ, whisper на модели `base` ~285 МБ, подпроцесс `claude`
до ~300 МБ. Без потолка связка способна исчерпать память машины и уронить
соседние сервисы.

Если на сервере меньше 2 ГБ — добавь swap:

```bash
ssh root@ТВОЙ_СЕРВЕР 'fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile && echo "/swapfile none swap sw 0 0" >> /etc/fstab'
```

## 6. Голосовые сообщения

Claude не принимает звук, поэтому нужен отдельный распознаватель.
Ставим `whisper.cpp` на сервер — бесплатно и без сторонних сервисов.

```bash
ssh root@ТВОЙ_СЕРВЕР 'bash -s' <<'EOF'
apt-get install -y build-essential cmake git ffmpeg
git clone --depth 1 https://github.com/ggml-org/whisper.cpp /opt/whisper.cpp
cd /opt/whisper.cpp
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j1
bash ./models/download-ggml-model.sh base
ln -sf /opt/whisper.cpp/build/bin/whisper-cli /usr/local/bin/whisper-cli
EOF
```

Сборка на одном ядре занимает несколько минут. Затем добавь в `.env`
на сервере:

```
WHISPER_BIN=/usr/local/bin/whisper-cli
WHISPER_MODEL=/opt/whisper.cpp/models/ggml-base.bin
WHISPER_LANG=ru
WHISPER_THREADS=1
```

Перезапусти: `ssh root@ТВОЙ_СЕРВЕР 'systemctl restart fin-bot'`

### Курсы валют

По умолчанию используется open.er-api.com: без ключа, около 160 валют,
один запрос отдаёт сразу все курсы.

Для Беларуси есть альтернатива — официальные курсы Нацбанка:

```
FX_SOURCE=nbrb
BASE_CURRENCY=BYN
```

Она точнее для BYN и знает историю по датам, но работает только когда
базовая валюта — белорусский рубль, и опрашивает каждую валюту отдельным
запросом.

### Какую модель выбрать

Замерено на 1 ядре AMD EPYC с AVX2, русская речь:

| Модель | Время на сообщение | Пик памяти | Качество |
|---|---|---|---|
| `base` | 5–6 сек | 285 МБ | суммы верно, редкие слова путает |
| `small` | 21–24 сек | 747 МБ | верно всё |

По умолчанию `base`: суммы обе берут одинаково, а вчетверо большее ожидание
того не стоит. Переезд на `small` — правка `WHISPER_MODEL` и подъём
`MemoryMax` в юните, пересборка не нужна.

Бот показывает расшифровку перед ответом, чтобы ошибка распознавания была
видна сразу, а не выяснялась потом по кривой записи.

## 7. Автоприём СМС от банка

Работает только на **macOS**: уведомления о тратах приходят на айфон, через
пересылку сообщений попадают на мак и лежат в базе Messages. Наблюдатель
читает их и передаёт боту.

```
мак: launchd, как только меняется база Messages (и раз в минуту на всякий)
  └─ читает ~/Library/Messages/chat.db (новее последнего ROWID)
     └─ отбирает сообщения нужной карты
        └─ SSH → сервер → dist/cli/ingest-sms.js
           └─ записывает операции и шлёт сводку с остатком в Телеграм
```

Задание разбудит `WatchPaths`: launchd следит за каталогом Messages и за
журналом `chat.db-wal`, поэтому трата попадает в бухгалтерию через
пару секунд после СМС, а не ждёт очередного опроса. Чаще раза в 10 секунд
задание не запускается (`ThrottleInterval`), а `StartInterval` раз в минуту
остаётся подстраховкой на случай, если событие потеряется. Холостой прогон
дешёвый: когда новых СМС нет, наблюдатель читает базу и выходит, никуда
не подключаясь.

Передача идёт по SSH, а не по HTTP: канал уже настроен и доверен, на сервере
не открывается ни одного порта наружу.

### Проверить, что СМС доходят до мака

Настройки → Сообщения → Пересылка сообщений — мак должен быть включён.

### Настроить сервер

Добавь в `.env` на сервере:

```
SMS_CARD=MIR-1234
SMS_CARD_ACCOUNT=Карта RUB
SMS_CASH_ACCOUNT=Наличные RUB
SMS_SINCE=2026-01-01
SMS_DRIFT_ALERT=50
```

- `SMS_CARD` — идентификатор карты, как он выглядит в тексте СМС
- `SMS_CARD_ACCOUNT` — счёт в боте, куда писать операции (должен существовать)
- `SMS_SINCE` — операции строго с этой даты; так прошлые траты не хлынут
- `SMS_DRIFT_ALERT` — с какого расхождения с банком (в рублях) поднимать
  тревогу; по умолчанию 50, значение `0` вернёт сообщение о любом,
  вплоть до копейки
  в бота при первом запуске

### Настроить мак

```bash
cp mac/watcher.env.example mac/watcher.env
```

Заполни `mac/watcher.env` своими значениями (файл в `.gitignore`):

```
SSH_TARGET=root@ТВОЙ_СЕРВЕР
SMS_CARD_PREFIX=Счёт карты MIR-1234
SMS_SINCE=2026-01-01
SMS_SENDER=900
```

`SMS_CARD_PREFIX` — начало текста СМС. Открой своё сообщение от банка
и скопируй начало строки дословно.

Установи:

```bash
npm run build
./mac/install.sh
```

### Выдать полный доступ к диску

Без этого база Messages не читается.

1. Системные настройки → Конфиденциальность и безопасность →
   **Полный доступ к диску**
2. Нажми `+`
3. В диалоге выбора файла нажми **`Cmd + Shift + G`**
4. Вставь путь: `~/.local/bin/finbot-node`
5. Убедись, что переключатель включён

> Шаг 3 обязателен: `.local` — скрытая папка, в обычном просмотре Finder
> её не показывает.
>
> Установщик делает отдельную копию `node` намеренно. Полный доступ к диску
> выдаётся конкретному файлу; если выдать его системному `node`, читать
> защищённые данные сможет любой node-скрипт на машине.

### Проверить

```bash
# показать, что нашлось, ничего не записывая
SMS_DRY_RUN=1 SMS_SINCE=2020-01-01 ~/.local/bin/finbot-node dist/mac/watch-sms.js

# запустить задание сейчас
launchctl kickstart -p gui/$UID/local.finbot.sms

# логи
tail -f ~/Library/Logs/fin-bot/sms-watch.log
```

### Что понимает парсер

Покупки в рублях и в валюте со списанием в рублях, оплаты, снятие и внесение
наличных, возвраты и отмены, покупку с выдачей наличных (одно СМС — две
операции), отложенные уведомления с датой.

Форматы разбирались на СМС Сбербанка. Для другого банка правь
`src/core/sms.ts` — там регулярные выражения и тесты рядом.

Незнакомая форма сообщения **пропускается, а не угадывается**: неверная
запись портит всю последующую аналитику.

### Наличные и сверка

Снятие в банкомате записывается **переводом** на счёт наличных, а не
расходом: деньги не потрачены, а переложены в карман. Трата фиксируется,
когда ты её назовёшь.

Каждое СМС содержит остаток по версии банка. Он сравнивается с расчётом бота;
при расхождении сводка предупреждает — значит, часть операций мимо бота.

## 8. Если что-то не работает

### `Not logged in · Please run /login`

Claude CLI не авторизован. Выполни `claude setup-token` и положи токен
в `.env` как `CLAUDE_CODE_OAUTH_TOKEN`. На сервере проверь, что CLI
установлен: `claude --version`.

### Бот молчит на любое сообщение

Проверь `OWNER_ID` в `.env` — он должен совпадать с твоим числовым ID.
Если оставить пустым, бот на первое сообщение ответит твоим ID.

Посторонним бот не отвечает намеренно: любой ответ подтвердил бы, что бот
существует.

### `unable to open database file` в логе наблюдателя

Не выдан полный доступ к диску для `~/.local/bin/finbot-node` (см. раздел 7).

### Наблюдатель ничего не находит

Проверь, что `SMS_CARD_PREFIX` дословно совпадает с началом твоих СМС,
и что `SMS_SINCE` не в будущем. Холостой прогон покажет, что видит наблюдатель:

```bash
SMS_DRY_RUN=1 SMS_SINCE=2020-01-01 ~/.local/bin/finbot-node dist/mac/watch-sms.js
```

### Сервис падает после выката

```bash
ssh root@ТВОЙ_СЕРВЕР 'journalctl -u fin-bot -n 50 --no-pager'
```

Частое: не хватило памяти (подними `MemoryMax` или добавь swap), либо файл
миграции не доехал в `dist/` — проверь `ls /opt/fin-bot/dist/db/migrations/`.

### Бот отвечает медленно

10–30 секунд — норма: агент делает несколько ходов с инструментами.
Быстрые команды (`/balance`, `/month`, `/cat`, `/due`, `/forecast`) считаются
без Claude и отвечают мгновенно.

## Оплаты Apple Pay с айфона

Нужно, когда банк не шлёт СМС, а платишь картой через Apple Pay.
Источник данных здесь — сам айфон, а не банк.

С iOS 17 в Быстрых командах есть триггер «Транзакция» (раздел Wallet
и Apple Pay). Он даёт название магазина, сумму и валюту. Важные границы:
срабатывает **только** на оплату телефоном или часами — физическая карта
в терминале, покупки в интернете и снятие в банкомате мимо.

Сумма приходит строкой вида `Br 22,27`, поэтому разбирает её сервер,
а не команда: там такой разбор не написать и нечем проверить.

### На сервере

`APPLEPAY_ACCOUNT` в `.env` — счёт, на который ложатся эти траты.

Доступ с телефона заперт на одну команду. Отдельный пользователь
`finpay` с заблокированным паролем; служебному `finbot` вход по SSH
не открывается — иначе взлом самого бота дал бы возможность прописать
себе постоянный доступ:

```bash
useradd --create-home --shell /bin/bash finpay && passwd -l finpay
echo 'finpay ALL=(finbot) NOPASSWD: /usr/local/sbin/finbot-applepay-run' \
  > /etc/sudoers.d/finbot-applepay && chmod 440 /etc/sudoers.d/finbot-applepay
install -d -m 700 -o finpay -g finpay /home/finpay/.ssh
```

Публичный ключ телефона кладётся с принудительной командой — что бы
клиент ни прислал, выполнится только приём оплаты:

```bash
command="/usr/local/sbin/finbot-applepay-receive",restrict ssh-ed25519 AAAA... phone
```

Проверить, что замок держит (обе команды должны вернуть «Пустой вход»,
а не содержимое файла и не оболочку):

```bash
ssh -i ключ finpay@СЕРВЕР 'cat /opt/fin-bot/.env' </dev/null
```

### На айфоне

1. Быстрые команды → Автоматизация → Новая → **Транзакция**
2. Выбрать нужную карту, включить **Запускать сразу**
3. Действие **Выполнить скрипт по SSH**: хост, пользователь `finpay`,
   ключ. Команда любая — сервер её игнорирует.
4. Ввод — текст:

```
{"id":"UUID","merchant":"НАЗВАНИЕ","amount":"СУММА","currency":"КОД"}
```

Вместо заглавных подставить переменные: `UUID` из действия «UUID»,
остальные — из «Вход быстрой команды» (Название, Сумма, Код валюты).

`id` обязателен: по нему отсекается повторная доставка одной и той же
оплаты. Две одинаковые покупки подряд получат разные UUID и запишутся
обе, а вот дважды доехавшая одна покупка деньги не удвоит.

### Проверка

Пробуй заведомо негодной суммой, а не настоящей: удачная проверка
запишет реальную трату в бухгалтерию и пришлёт сообщение.

```bash
echo '{"id":"проба","merchant":"X","amount":"не число"}' \
  | ssh -i ключ finpay@СЕРВЕР
```

Ответ `{"recorded":0,...,"rejected":1}` означает, что канал живой.

### Расхождение с банком в сводке

Ожидаемо, если бот не знает историю счёта до `SMS_SINCE`. Скажи ему
«на карте RUB сейчас столько-то» — дальше сверка станет осмысленной.

Мелкий сдвиг в копейки обычно остаётся навсегда: он появился на первой
сверке и просто переносится дальше, не накапливаясь. Такое расхождение
ни о чём не говорит, поэтому по умолчанию бот молчит обо всём, что меньше
50 рублей — порог задаётся в `SMS_DRIFT_ALERT`. Расхождение пишется
в таблицу `balance_checks` в любом случае, так что историю можно посмотреть:

```bash
sqlite3 data/finance.db "SELECT * FROM balance_checks ORDER BY id DESC LIMIT 20;"
```

Если расхождение растёт от сверки к сверке — вот это уже значит, что
операции действительно не доходят.
