# Телеграм-бот «Финансовый консультант» — дизайн

**Дата:** 2026-08-19
**Статус:** утверждён

## Задача

Персональный телеграм-бот для одного пользователя (@fwexxo): мини-бухгалтерия в трёх
валютах (RUB, BYN, USD), учёт постоянных месячных расходов с напоминанием о сроках
оплаты, аналитика и прогноз по собственным деньгам.

## Границы

**В объёме:** учёт доходов и расходов, мультивалютные счета, регулярные платежи и
упреждающие напоминания, отчёты по категориям и периодам, прогноз свободных средств.

**Вне объёма:** персональные инвестиционные рекомендации. Бот считает и объясняет
собственные деньги пользователя и общие понятия; решения о вложениях остаются за
пользователем. Это осознанное ограничение, а не недоработка.

## Ключевые решения

### Три слоя с разной природой

| Слой | Реализация | Почему так |
|---|---|---|
| Учёт | TypeScript + SQL | Цифры должны быть воспроизводимыми и проверяемыми. LLM здесь недопустим. |
| Разбор текста | Claude (structured output) | Свободный ввод «кофе 5 руб» — задача, где LLM объективно сильнее правил. |
| Консультант | Claude + read-only SQL | Открытые вопросы по своим данным. Считает SQL, интерпретирует Claude. |

Граница между слоями жёсткая: слой учёта не знает о существовании Claude и полностью
тестируется без него.

### Деньги — целые числа в минорных единицах

Все суммы хранятся как `INTEGER` в копейках. Хранение денег во float даёт накопление
ошибки округления, которое в бухгалтерии проявляется расхождением баланса и не
локализуется постфактум.

### Мультивалютность: счета в своей валюте + курс на дату

Каждый счёт имеет ровно одну валюту. Транзакция хранит сумму в валюте счёта **и**
курс к базовой валюте на дату операции (`fx_rate_to_base`).

Это даёт одновременно:
- реальный баланс каждого счёта, не искажённый переоценкой;
- сводный отчёт в базовой валюте (BYN), устойчивый к последующему движению курса.

Альтернатива «конвертировать всё в базовую при записи» была отвергнута: она теряет
фактические балансы по счетам и делает невозможным ответ на вопрос «сколько у меня
долларов».

Источник курсов — открытое API Нацбанка РБ (BYN/USD/RUB). Курс на дату кешируется в
таблице `fx_rates`; повторные запросы за ту же дату к сети не ходят.

### Подтверждение перед записью

Разобранная транзакция показывается карточкой с кнопками `[Записать] [Категория ▾]
[Отмена]` до попадания в БД. Неоднозначности во вводе неизбежны («500» — рублей или
тысяч; «вчера» при вводе после полуночи), а молча записанная неверная сумма портит всю
последующую аналитику и обнаруживается поздно.

## Модель данных

```
accounts           id, name, currency, kind(cash|card|deposit), is_active
categories         id, name, parent_id, kind(expense|income)
transactions       id, ts, account_id, amount_minor, currency, category_id,
                   direction(expense|income|transfer), counter_account_id,
                   note, raw_text, fx_rate_to_base, created_at
recurring_payments id, title, account_id, amount_minor, currency,
                   day_of_month, is_last_day, is_variable,
                   remind_days_before, is_active
payment_instances  id, recurring_id, period(YYYY-MM), due_date,
                   status(pending|paid|skipped), paid_tx_id
fx_rates           date, base, quote, rate            -- PK (date, base, quote)
budgets            id, category_id, period, limit_minor, currency
schema_migrations  version, applied_at
```

Переводы между счетами моделируются как транзакция `direction='transfer'` со ссылкой
на `counter_account_id` — это позволяет корректно исключать их из отчётов о расходах.

`payment_instances` отделены от `recurring_payments` намеренно: правило («интернет 15-го
числа») и конкретный факт («интернет за август, 30 BYN, оплачен») — разные сущности с
разным жизненным циклом.

### Срок платежа: число месяца или «последнее число»

Реальные платежи пользователя делятся на две группы:

| Группа | Состав | Срок | Валюта |
|---|---|---|---|
| Белорусская | интернет, коммуналка, связь, аренда квартиры, абонемент в зал | 15-е число | BYN |
| Российская | серверы и прочие сервисы | последнее число месяца | RUB |

«Последнее число» — не фиксированный день: это 28, 29, 30 или 31 в зависимости от
месяца и високосности года. Поэтому срок задаётся двумя полями, а не одним числом:

- `is_last_day = 1` → срок вычисляется как последний день конкретного месяца;
- иначе `day_of_month` → срок с обрезкой по длине месяца (правило «31-го» в феврале
  даёт 28 или 29 февраля, а не переносится на март).

Один INTEGER-столбец здесь недостаточен: значение «31» означает «31-го числа, а если
такого нет — в последний день», что для февраля совпадает с «последним числом», но для
апреля означает 30-е — то же самое. Различие проявляется на 30-дневных месяцах только
при значениях 29 и 30, и полагаться на это совпадение хрупко. Явный флаг выражает
намерение однозначно.

## Поток обработки сообщения

```
входящее сообщение
  └─ from.id == OWNER_ID ?  ── нет ─→ игнор (без ответа)
       │ да
       ├─ команда (/balance, /month, …) ─→ детерминированный обработчик
       └─ свободный текст
            ├─ очередь Claude (concurrency = 1)
            ├─ парсинг → {amount, currency, category, date, direction}
            ├─ карточка подтверждения
            └─ подтверждено → запись в БД → показ нового баланса
```

## Напоминания

Ежедневная задача в 10:00 (Europe/Minsk):

1. Достроить `payment_instances` для текущего месяца по активным правилам.
2. Найти инстансы со `status='pending'` и `due_date - remind_days_before <= сегодня`.
3. Отправить сообщение с кнопкой `[Оплачено]`.

Кнопка создаёт транзакцию и переводит инстанс в `paid`. Для `is_variable=true` бот
сначала спрашивает фактическую сумму.

Повторные напоминания шлются раз в сутки до оплаты; каждое сообщение редактируется, а
не дублируется, чтобы чат не засорялся.

## Ресурсы и устойчивость

Claude Agent SDK запускает `claude` CLI подпроцессом. На VPS (1 CPU, 2 ГБ RAM):

- очередь Claude-вызовов с конкурентностью 1;
- systemd `MemoryMax=700M` — бот физически не может исчерпать память машины;
- `Restart=always`, `RestartSec=5`.

## Безопасность

- Доступ строго по числовому `OWNER_ID`. Whitelist по username отвергнут: username в
  Telegram можно сменить и передать другому человеку, числовой ID постоянен.
- Токен бота и все секреты — в `.env`, который в `.gitignore`. Репозиторий приватный.
- База данных — локальный файл на VPS, наружу не публикуется. Открыт только SSH.

## Тестирование

Слой учёта покрывается unit-тестами без сети и без Claude: арифметика балансов,
конвертация по зафиксированному курсу, генерация `payment_instances` на границах месяца
(28/29/30/31 число), корректность исключения переводов из отчётов о расходах.

Разбор текста тестируется на фиксированном наборе фраз с проверкой структуры вывода, а
не точного текста.
